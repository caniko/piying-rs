## Decisions

### Ported correctness changes

- `ae17f01`: capture shutdown-hook panics using the same panic representation as
  startup hooks; always publish the shutdown result after normal cleanup.
  Lifecycle callback lock-release fixes are already present locally.
- `bddbbf0`: complete the existing front-buffer port in `recv_many()` and `len()`.
  Piying has no upstream restart supervisor or child-mailbox drain loop to port.
- `e8a0bce`: share message acceptance state across strong/weak mailbox handles;
  reject all new message send variants once graceful stop is polled, while
  continuing to deliver lifecycle/link signals and the already-queued backlog.
- `ceb672e`: preserve pool worker errors with the correct `WorkerReply` associated
  types. This changes the public error type and requires the next release to be
  0.2.0 rather than a 0.1.x patch.

The regression work also identified local defects: strong shutdown waits returned
at mailbox closure before `on_stop` finished; enqueue/forward failures downcasted
messages to the wrong types; batch metrics used an underflowing/off-by-one slice.
These shared paths are fixed and covered by runnable checks.

### Deferred and inapplicable changes

- Supervision drain/restart fixes require the upstream restart supervisor,
  `ErasedChildSpec`, and restart-budget machinery, which Piying does not have.
- Message-span fixes require upstream per-message tracing spans, which Piying
  does not create.
- Console, pipe-to-self, default reply timeouts, undelivered-message hooks,
  single-Arc actor handles, and FutureActor remain separate feature candidates.
  The console adds a TCP/MessagePack monitoring interface; the actor-handle
  refactor changes reference-count semantics; neither is a small correctness port.
- The fake-time mailbox tests depend on Tokio test-time control and interact with
  the old hotpath proxy runtime. Existing tests pass; new mailbox regressions wait
  for actual delivery rather than assuming synchronous proxy delivery. No tests
  were disabled. The scheduler example is already `no_run` locally.
- Hotpath 0.21 changes channel endpoint types and backpressure instrumentation.
  Retain 0.11 for this sync. OpenTelemetry is absent from Piying.
- Syn 3 requires macro parser API migration without a demonstrated current need.
- Libp2p 0.57 changes remote event types and registry handling; defer coordinated
  codec/Regicide migration while retaining the 0.56 production P2P contract.
- Do not add upstream `PanicError::is_panic`: checking only `HandlerPanic` does not
  identify unwinding lifecycle hooks. Preserve Piying's existing reason API.

## Validation and release hold

Passed checks include workspace default/all-features tests, both remote codec
matrices, minimal-feature tests, all-targets Clippy with denied warnings for both
all-features and minimal features, Rust 1.88 all-features compilation,
warning-free workspace rustdoc, verified workspace packages and registry
dry-runs, treefmt, and Simit generator/hook checks.
The new regressions reproduced the shutdown, pool, graceful-stop, forwarding,
and mailbox failures before their fixes.

The MSRV hook now selects both Cargo and rustc 1.88 explicitly, preventing a
newer compiler on the development PATH from masking an MSRV failure. Nix
development-shell evaluation succeeded; standalone `nix flake check` was denied
by the execution harness and is not recorded as passed.

Regicide validation used an isolated copy of its unmodified `thespan` sources,
with a path dependency on this Piying checkout and Regicide's existing relay,
swarm, disabled-DNS, and disabled-mDNS patches. All four unit tests and the
WebRTC Direct peer connection/message-exchange integration test passed. This
checks the actor-networking consumer without changing Regicide's checkout or
claiming a full gameplay/Steam validation.

Compatible dependency refreshes fixed the audit findings in crossbeam, HTTP/2,
QUIC, rkyv, and TLS. The remaining audit failures are `RUSTSEC-2026-0118` and
`RUSTSEC-2026-0119` in `hickory-proto 0.25.2`, reached through the dependency
chain `piying → libp2p 0.56 → libp2p-mdns 0.48`. RustSec marks the first unaffected
from 0.26.0-beta.1 (its DNSSEC implementation moved out of hickory-proto), and
the second patched from 0.26.1. No compatible 0.25 fix is available in the
current dependency resolution.

On 2026-09-30 the operator authorized narrow exceptions for exactly these two
advisories so local commits and pushing can proceed. The exceptions live only
in the `cargo-audit` commit hook in `nix/pre-commit.nix`; there is no global
audit ignore configuration. Remove them when the libp2p/mDNS chain gains a
compatible fix or the coordinated dependency migration is completed.

`RUSTSEC-2026-0118` requires DNSSEC validation features, which this checkout's
mDNS chain does not enable. `RUSTSEC-2026-0119` concerns CPU amplification during
DNS name compression and remains a dependency risk accepted for committing,
not for publication. Regicide's production dependency patches disable mDNS,
but Piying's general remote feature retains it.

The Simit `release-audit` required gate runs plain `cargo audit` in CI and as a
prerequisite of every coordinated publish job. It deliberately has no advisory
exceptions, so the current dependency findings continue to block publication.

The operator explicitly selected **hold release** on 2026-09-30. Keep all
versions unchanged, retain the failed audit as a blocker, and do not push a
publishing tag until the dependency issue is resolved and release gates pass.

### Advisory resolution — 2026-10-01

The follow-up security migration supersedes the libp2p 0.57 deferral and Hickory
audit hold above. Piying now uses libp2p 0.57.0 and libp2p-mdns 0.49.0, with
Hickory 0.26.3 in the lockfile and an explicit minimum version in the remote
feature's dependencies. That floor also protects downstream consumers whose
dependency resolution is independent of Piying's checked-in lockfile.

The rkyv codec implements the native async `request_response::Codec` interface,
and registry lookup handling no longer matches libp2p's removed
`GetRecordError::QuorumFailed` variant. Piying retains the published rkyv framing
helpers; their older libp2p dependency does not retain vulnerable Hickory.
Protocol identifiers, rkyv framing, and the Rust 1.88 minimum are preserved.
`RoutingUpdated::addresses` is boxed so the larger upstream address collection
does not inflate every registry and remote event; owning consumers dereference
the box to obtain `kad::Addresses`.
Regicide's libp2p 0.56 networking and patch set require a coordinated 0.57 update
before consuming this release; the earlier downstream results cover the 0.56
baseline.

Follow-up all-feature validation reproduced races in the mailbox tests when
Hotpath 0.11 forwards through its separate channel. The metrics test now holds
capacity directly for the cancellation assertion and waits for sender closure;
the full-mailbox integration tests fill the proxy and in-flight forwarding slot
as well. Acceptance, backlog ordering, pending sends, and count-once assertions
remain covered, including repeated runs with and without Hotpath.

Plain `cargo audit` against the migrated lockfile reports no vulnerabilities;
the existing `paste` unmaintained warning remains informational. The two local
commit-hook exceptions have been removed. The public networking-type migration
joins the pool error-type change in requiring a 0.2.0 release. Release tagging
still requires the remaining release gates to pass.
